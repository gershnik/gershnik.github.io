Certificates

When a connection is established, the remote Windows machine presents a certificate identifying itself.

If that certificate is already trusted by your Mac’s Keychain, the connection proceeds without asking you anything.

Otherwise, the certificate is shown to you and you are asked whether to trust it. Review the certificate carefully before accepting it.

Trusting a certificate for a connection

If you choose to trust an unrecognized certificate, the application saves that exact certificate with the connection.

From then on, that connection will accept the same certificate without prompting you again. If the server later presents a different certificate, you will be asked to review it.

This trust applies only to that particular connection. The certificate is not added to your Keychain, and trusting it here does not make it trusted by other applications or by macOS in general.

This model is sometimes called trust on first use, or TOFU.

Reviewing or removing a saved certificate

A certificate previously accepted for a connection can be viewed in that connection’s properties.

You can also remove it there. The next time the connection encounters a certificate that is not otherwise trusted by your Keychain, you will be asked to review it again.

Exporting certificates

Whenever a certificate is displayed, you can export it to a file.

This can be useful if you want to inspect it with another tool, keep a copy, or import it into your Keychain yourself.

The application never adds, removes, or modifies certificates in your Keychain.

Programmatic connections

One-off programmatic connections do not have a saved application connection record, so there is nowhere to store a connection-specific trusted certificate.

For these connections, if the server certificate is not already trusted by your Keychain, you will be prompted to review it each time. To avoid that prompt, add the certificate to your Keychain yourself.
